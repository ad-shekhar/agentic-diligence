GOVERNANCE & INTEGRITY

Engineered for Verifiable Mathematical Trust

Agentic Diligence is built on strict epistemic foundations. We do not invent trust scores, fabricate compliance badges, or assume unobserved software behavior succeeded.

Rule 1: Verify What Evidence Supports

Founder statements, pitch decks, and contractual SLAs are treated as unverified vendor claims (T0). A claim is only verified when empirical runtime telemetry confirms the target criteria within confidence bounds.

Rule 2: Absence ≠ Evidence of Absence

If an agent runtime lacks telemetry for a 15-minute interval, that interval is classified as [UNKNOWN]. It is never assumed to be autonomous, zero-cost, or successful. Unknowns widen statistical bounds.

Rule 3: Dark-Zone Threshold (35% Rule)

If more than 35% of an agent's execution tasks lack telemetry evidence, claims requiring high autonomy or completion are capped at PARTIALLY_VERIFIED or INSUFFICIENT_EVIDENCE regardless of observed success rates.

Rule 4: Explicit Epistemic Tagging

Every single number emitted by Agentic Diligence is tagged with its origin: [OBSERVED] (directly measured in spans), [CALCULATED] (derived via deterministic math), [INFERRED] (heuristic), or [UNKNOWN].

Data Privacy & Automated Redaction

Agentic Diligence is designed to audit agent execution without leaking intellectual property, end-user personal data, or infrastructure credentials:

Credential Scrubbing

Incoming payloads automatically sanitize API keys (sk-...), GitHub tokens (ghp_...), and HTTP Authorization headers before database storage.

Hermetic Manifest Containment

Manifest verification strictly enforces directory containment (os.path.commonpath), rejecting directory traversal sequences (..) and absolute host path escapes.

Local & Air-Gapped Operation

The platform can execute completely offline in air-gapped auditor sandboxes without phoning home or transmitting telemetry to cloud servers.
